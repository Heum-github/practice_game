## 플레이 피드백 2차 (2026-08-30) — v0.4.1 **처리 완료**

v0.4까지 올린 뒤 다시 플레이해서 나온 것들. 1차와 성격이 다르다 —
**"고쳤다고 적어둔 것이 플레이어에게는 없는 것과 같았다"**가 절반이다.
기능은 들어가 있는데 아무도 그 존재를 몰랐고, 그건 기능이 없는 것과 똑같다.

| | 증상 | 원인 |
|---|---|---|
| C1 | **방벽을 한 방향으로만 세울 수 있다 · 철거를 못 한다** (D1·D3의 재발) | 기능은 둘 다 있었다. `R`도 `X`도 **어디에도 적혀 있지 않았고**, 미리보기는 방향이 바뀌어도 똑같은 네모였다. 눌러도 달라지는 게 없으니 없는 기능이다 |
| C2 | **길잡이가 왼쪽 위 정보를 가린다** | 길잡이의 `top: 96px` 이 고정값이었다. v0.4에서 시계 패널에 '정착지' 줄이 하나 늘어 패널이 147px 로 자랐고, 그만큼 날짜와 계절을 덮었다 |
| C3 | **요리가 단추 한 번에 끝난다** | 화톳불이 "곁에 있어야 하는 조건"일 뿐 **머무는 장소**가 되지 못했다 |
| C4 | **도감에 식물과 음식이 한 목록에 섞여 있다** | 기르는 이야기와 익히는 이야기와 세계가 나빠지는 이야기가 여섯 줄로 뒤엉켰다 |
| C5 | **죽고 살아나면 보관함과 문이 만져지지 않는데 그림은 그대로 남는다** | `Buildings.reset()` 이 메시를 **손으로 나열해서** 지웠다. v0.3~0.4에서 늘어난 문·퇴비·함정·작업대·보관함이 그 목록에 없었다. 자료는 지워지고 그림만 살아남은 것이다 |

**처리 결과**

| | 어떻게 고쳤나 |
|---|---|
| C1 | 방벽·문이 **옆 칸을 보고 알아서 돌아선다**(`suggestRotation`). 줄을 긋다 모퉁이에서 꺾으면 벽도 같이 꺾인다. `R` 은 자동 → 가로 → 세로 로 도는 덮어쓰기로 남기고, 미리보기 판을 **방향대로 눕혀** 눌렀을 때 무엇이 달라지는지 보이게 했다. 철거는 뜯을 수 있는 것을 보고 있을 때 `X (길게) — …철거` 가 그 자리에 뜬다. 조작 안내에도 둘 다 넣었다. 겸사겸사 방벽 판을 0.92m → 1.0m 로 넓혔다 — 칸이 1m 인데 판이 좁아 줄마다 8cm 씩 틈이 났다 |
| C2 | Hud 가 시계 패널의 아랫변을 `--hud-clock-bottom` 으로 **재서 넘긴다**. 줄이 또 늘어도 길잡이가 알아서 내려간다. 숫자를 고치는 것은 다음 줄이 늘 때까지만 맞는 답이다 |
| C3 | 화톳불 조리에 **시간**이 붙었다 (`Recipe.cookTime`). 재료는 올릴 때 가져가고 결과는 다 되었을 때 준다. 자리를 뜨거나 **불이 꺼지면 중단되고 재료는 그대로 돌아온다** — 손해가 나면 아무도 불 앞에 앉지 않는다 |
| C4 | 도감을 **식물 · 조리 · 땅과 계절** 세 갈래로 나눴다. 갈래마다 마지막으로 보던 항목을 기억한다 |
| C5 | `reset()` 이 종류 표(`ALL_KINDS`)를 돌며 `meshesFor(kind)` 로 지운다. `dispose()` 도 같이 고쳤다. 손으로 나열하는 목록은 종류가 늘 때마다 반드시 어긋난다 |

**덤으로 하나 더.** 도감 패널이 부팅 중에 **두 번 만들어지고 있었다.** 두 번째가 첫 번째를
덮어써서 첫 번째는 아무도 닫을 수 없는 채로 DOM 에 남았다 — 1차 피드백의
"탭이 없어지지 않는다"의 진짜 정체가 이것이었을 가능성이 높다.
