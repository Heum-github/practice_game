## 8. 품질 설계 — 무엇이 이 게임을 "좋아 보이게" 하는가

기능이 다 있어도 조잡해 보일 수 있고, 기능이 적어도 좋아 보일 수 있다.
그 차이를 만드는 것을 다섯 축으로 나누고, **비용 대비 효과**로 줄을 세운다.
새 기능을 넣기 전에 이 표의 위쪽이 비어 있지 않은지 먼저 본다.

### 8.1 다섯 축

| 축 | 질문 | 지금 상태 |
|---|---|---|
| **동작** | 캐릭터가 살아 있는 것처럼 움직이는가 | 보행 주기 모델 적용 완료 |
| **반응** | 내 행동에 세계가 답하는가 | 먼지·화면 흔들림·화각 적용 |
| **시각** | 한 장면을 멈춰 세워도 볼 만한가 | AO·매끄러운 지형·전선·자갈 |
| **정보** | 지금 무엇을 해야 하는지 화면이 말해주는가 | 나침반·거점 칩·프롬프트 |
| **밀도** | 세계가 비어 보이지 않는가 | 인스턴스 11,700여 개 |

### 8.2 우선순위

효과가 크고 비용이 작은 것부터. 위 세 줄이 끝나기 전에 아래로 내려가지 않는다.

| 순위 | 항목 | 축 | 왜 |
|---|---|---|---|
| ~~1~~ | **소리** | 반응 | **완료** — 음원 파일 없이 Web Audio 로 합성한다. 발소리·타격·피격·설치·바람·불 |
| 2 | **정지·회전 모션** | 동작 | 멈출 때 발이 미끄러지고, 제자리에서 도는 동작이 없다. 걷기를 고친 만큼 여기가 눈에 띈다 |
| ~~3~~ | **타격 반응** | 반응 | **완료** — 히트스톱 0.07초 + 생물이 눌렸다 돌아오는 움찔 자세 |
| ~~4~~ | **원경 실루엣** | 시각 | **완료** — 시점을 따라다니는 고리형 배경 도시 (210조각) |
| ~~5~~ | **날씨** | 시각·밀도 | **완료** — 비는 밭을 적시고, 먼지폭풍은 앞을 가리고 밭을 말린다 |
| ~~6~~ | **폐허 내부** | 밀도 | **완료** — 출입구를 보장하고, 지붕 아래에서는 비바람이 걷힌다 |
| ~~7~~ | **작물·설비 시각 단계** | 시각 | **완료** — 새싹·잎·이삭 세 단계의 형상을 따로 두어 성장이 화면에서 읽힌다 |

### 8.3 반복해서 지킬 규칙

작업하며 실제로 발목을 잡았던 것들이라 원칙으로 남긴다.

- **색은 16진(sRGB)으로 적는다.** three.js는 실수 인자를 선형으로 읽어 두 배 밝게 낸다
- **매 프레임 배열을 만들지 않는다.** `filter` 네 번이 CPU를 여섯 배로 만든 적이 있다
- **인스턴스 버퍼는 바뀐 것만 올린다.** 작물 성장을 양자화한 이유
- **CSS 애니메이션에 상태를 맡기지 않는다.** 배경 탭에서 멈춰 화면이 굳는다
- **연출은 프레임에서 감쇠시킨다.** 시간 기반이어야 배속·정지와 어긋나지 않는다
- **완전한 평면을 만들지 않는다.** 매끄러운 셰이딩에서 균일한 밝기 덩어리로 드러난다
- **큰 것만 그림자를 던진다.** 잔부품까지 넣으면 드로우콜만 두 배가 된다
- **InstancedMesh 는 경계구를 다시 재준다.** count 0 으로 태어난 메시는  인
  빈 구가 박히고, 인스턴스를 채워도 갱신되지 않는다. 그대로 두면 시선 방향에 따라
  통째로 사라진다 — 밭이 안 보이던 이유가 이것이었다
- **내리막에서는 지면에 다시 붙여야 한다.** 수평으로 나아가면 발밑 지면이 꺼지는데
  중력만으로는 못 따라잡는다. 22도 비탈에서 60프레임 중 52프레임이 공중이었다
- **`Number(localStorage.getItem(x))` 를 그대로 검사하지 않는다.** 키가 없으면 null 이고
  `Number(null)` 은 0 이다. "유한하고 범위 안"을 통과해 볼륨이 0 으로 저장됐다
- **한 값을 두 가지 뜻으로 쓰지 않는다.** 핫바 번호를 가방 칸 번호로 읽어
  밭 일구기가 조용히 취소됐다. 타입이 같으면 컴파일러는 못 잡는다
- **물은 금속이 아니다.** metalness 를 올리면 알베도가 반사색이 되어 탁한 금속판이 된다.
  0 으로 두고 거칠기만 낮춰야 프레넬이 산다 — 내려다보면 어둡고 비스듬히 보면 하늘이 비친다
- **완벽히 평평한 반사면은 칠한 판으로 보인다.** 법선이 조금이라도 흔들려야 반사가 부서지고,
  그제야 물처럼 읽힌다. 요철은 2cm면 충분하다
- **면의 감김 방향은 법선 속성이 아니다.** three 는 정점 순서로 앞뒷면을 가른다.
  XZ 평면에 각도 순으로 삼각형을 찍으면 위에서 볼 때 뒷면이 되어 통째로 사라진다 — 웅덩이가 그랬다
- **계속 나는 소리는 창을 떠날 때 직접 멈춘다.** 브라우저는 배경 탭 오디오를 알아서 끄지 않는다
- **숨겨진 탭에서 잰 프레임 시간은 믿지 않는다.** rAF 가 스로틀돼 0.7ms 도 33ms 도 나온다.
  CPU 만 따로 재거나(렌더를 비워두고) 창을 띄운 상태에서 잰다
- **매 프레임 다시 계산하는 값에 덧씌울 때는 순서를 확인한다.** 날씨가 안개를 바꾸는데
  Sky 보다 먼저 돌아서 그대로 지워졌다. 값은 맞는데 화면만 그대로인 종류의 버그다
- **설치물을 살려내는 길이 둘이면 둘 다 손봐야 한다.** 새로 놓는 길에만 보관함 내용물을
  만들어 두었더니, 세이브에서 되살아난 보관함은 껍데기만 남아 열리지도 않고
  **저장된 물건이 조용히 사라졌다.** 생성자가 둘이면 초기화도 둘이다
- **칸을 그리는 곳이 둘이면 설명도 둘이 된다.** 가방만 아이콘으로 바꾸고 보관함을 잊어서,
  같은 물건이 창을 옮길 때마다 다른 얼굴이 됐다. 공용 부품으로 빼는 편이 결국 짧다
- **넣을 때만 합치면 한 번 쪼개진 것은 영영 갈라져 있다.** 12칸이 금세 잠긴다
- **천장은 최종값에 씌운다.** 포자 농도의 장기 추세를 2.6에서 막아 놓고 계절 배수(×2)를
  그 위에 곱했더니 실효 농도가 5를 넘었다. 2년차에 3.92배 — 숨만 쉬어도 6분이면 앓아눕는다.
  막아야 할 것은 중간 값이 아니라 **플레이어가 실제로 겪는 값**이다
- **캐시에는 값이 아니라 물건을 담는다.** 나침반 표지는 설치물이 늘고 줄 때만 다시 만든다.
  거기에 연료 잔량을 복사해 두면 그 순간부터 옛날 값이다 — 물건 자체를 들고 있다가
  그릴 때 읽으면 캐시를 유지하면서도 항상 최신이다
- **절차 생성 옆에 손으로 세운 것을 두려면 자리를 비워줘야 한다.** 종자고를 폐허 한복판에
  놓았더니 무너진 건물 조각 하나가 그 안에 박혔다. 겉으로는 멀쩡한데 **문을 열어도
  들어갈 수가 없었다** — 눈으로는 절대 안 보이고 콜라이더를 찍어봐야 나오는 종류다.
  생성기 쪽에 금지 구역을 하나 파는 것이 정답이다
- **공간 해시의 조회는 후보이지 답이 아니다.** `query` 가 돌려준 개수를 겹침으로 읽고
  "안까지 막혀 있다"고 판단할 뻔했다. 격자 한 칸(6m) 안의 것을 다 돌려주므로
  실제 겹침은 AABB 로 한 번 더 걸러야 한다
- **지붕을 덮으면 안은 완전한 암흑이다.** 종자고 안에 선반을 짜 넣었는데 들어가 보니
  검은 화면뿐이었다. 밖에서 만든 것을 안에서도 보이게 하려면 등이든 자체 발광이든
  광원을 같이 넣어야 한다 — 만들어 놓고 안 보이는 것은 만들지 않은 것과 같다
- **덮개는 그 밑을 지나는 길을 막는다.** 첨탑 꼭대기 발판을 계단을 덮을 만큼 넓게
  깔았더니 위쪽 일곱 칸이 발판 밑을 지나게 되어 머리가 천장에 걸렸다.
  계단은 멀쩡히 보이는데 중간에서 더 못 올라가는, **눈으로는 절대 안 보이는** 사고다.
  덮개는 지나는 길의 반지름보다 안으로 물린다
- **"올라갈 수 있는가"는 걸어보고 판단한다.** 챌면 0.32m / 디딤면 0.94m 라는 숫자만
  보고 통과라고 적을 뻔했다. 실제로 `player.step()` 을 돌려 계단을 걷게 해 보니
  절반쯤에서 막혀 있었다 — 기하는 맞고 충돌은 틀릴 수 있다
- **자기가 적어둔 진단도 숫자로 다시 확인한다.** "땅이 모자란다"고 문서에 적어두고
  무한 지형에 착수할 뻔했는데, 세어 보니 개척지가 쓰는 땅이 월드의 **0.16%**였다.
  틀린 문제를 아주 잘 푸는 것이 제일 비싸다
- **손으로 나열한 목록은 종류가 늘 때마다 어긋난다.** `Buildings.reset()` 이 메시를 하나씩
  적어 지웠는데, 뒤에 늘어난 문·퇴비·함정·작업대·보관함이 거기에 없었다. 죽고 살아나면
  **자료는 지워졌는데 그림만 그대로 서 있었다** — 만질 수 없는 껍데기다.
  종류 표를 돌게 하면 종류를 더해도 다시는 어긋나지 않는다
- **화면 좌표를 손으로 맞추지 않는다.** 길잡이의 `top: 96px` 은 적을 때는 맞았다.
  나중에 위 패널에 줄이 하나 늘자 그만큼 아래를 덮었다. 붙어 있어야 하는 것은
  **재서 넘긴다**(ResizeObserver → CSS 변수). 숫자를 고치는 것은 다음 줄이 늘 때까지만 맞는 답이다
- **아무도 모르는 기능은 없는 기능이다.** 방벽 회전(`R`)과 철거(`X`)는 만들어 놓고
  **조작 안내에 적지 않았고**, 눌러도 미리보기가 그대로였다. "한 방향으로만 세워진다",
  "철거할 수 없다"는 보고가 그래서 다시 올라왔다. 기능을 넣었으면 **눌렀을 때
  달라지는 것이 보여야** 하고, 되도록 **누르지 않아도 알아서 되게** 해야 한다
- **같은 것을 두 번 만들면 첫 번째는 아무도 닫을 수 없다.** 부팅 코드에 도감 생성이
  두 줄 있었다. 두 번째가 참조를 덮어써서 첫 번째는 DOM 에 남은 채 주인을 잃었다 —
  "창이 사라지지 않는다"는 이렇게 만들어진다
- **관절 부호는 추측하지 말고 재본다.** 무릎이 반대로 접혀 있었는데 화면으로는
  한참 몰랐다. 축을 한 번 돌려보고 월드 좌표를 찍으면 5분이면 끝난다
- **건물은 딱딱한데 땅은 아니다.** 온실을 중심 한 점의 높이로 통째로 앉혔더니
  기복 3.3m 인 자리에서 한쪽 허리벽은 완전히 파묻히고 반대쪽은 허공에 떠 있었다.
  화면에는 **건물이 통째로 안 보이고** 콜라이더는 땅속이라 벽을 그냥 통과한다.
  평탄한 자리를 찾는 것은 답이 아니다 — 월드를 전부 세어 보니 가장 나은 곳도
  2.33m 였다. **뼈대는 한 기준 높이(발자국 안 최고점)에 수평으로 고정하고,
  땅에 닿는 것만 구간마다 제 발밑을 다시 잰다.** 폐허의 `wall()` 이 이미 그렇게 한다
- **손으로 고른 좌표는 숫자로 확인한다.** 온실 자리의 지형이 험하면 `tooSteep`/
  `blocked` 가 자원 노드를 전부 걸러내, **건물은 서 있는데 올 이유가 없는** 상태가
  된다. 눈으로는 절대 안 보인다. 개발 훅이 실제로 깔린 개수를 돌려주게 해 두면
  0 이 뜨는 것으로 끝난다. 실제로 격납고가 잔해 0/30 으로 나왔다
- **공간 해시의 조회는 후보이지 답이 아니다 — 두 번째로 걸린 자리.**
  `ResourceNodes.blocked()` 가 `query` 결과를 높이만 보고 막힌 것으로 읽었다.
  격자 한 칸이 6m 라, **폐허와 구조물 주변 한 칸이 통째로 빈 땅**이 되어 있었다.
  격납고 반경 15m 의 82%가 막힌 것으로 나온 것이 그래서다. XZ 겹침을 한 번 더 건다
- **개수가 중요한 것은 확률이 아니라 목표로 정한다.** 위 버그를 고치자 같은
  확률로 흙이 31에서 50이 됐다 — **흙이 귀하다는 전제가 남의 버그 수정에 딸려
  움직인 것이다.** 확률을 도로 낮춰 맞추려 했지만 15%를 내리면 개수가 60% 뛰는
  식이라 두더지잡기가 됐다. 후보를 모아 **가중 추첨으로 목표 개수만큼** 고르면
  자리를 정하는 규칙은 그대로 살고 개수만 못 박힌다 (잔해·보급이 이미 그랬다)
- **난수는 종류마다 따로 쓴다.** 하나의 흐름을 나눠 쓰면 앞의 배치가 뽑아 쓴
  횟수만큼 뒤가 밀린다. 흙 확률만 만졌는데 풀과 물의 개수가 같이 움직여서,
  무엇이 무엇을 바꾼 건지 알 수가 없었다
- **지붕은 콜라이더가 있어야 지붕이다.** `updateShelter` 는 눈높이에서 위로
  광선을 쏘므로, 그리기만 하고 충돌을 빼면 **격납고 한복판에서 `shelter: 0`** 이
  나온다 — 지붕이 눈에는 보이는데 비를 맞는다. 사거리(7m)도 함께 봐야 해서,
  건물이 그보다 높으면 안에 들어가도 소용이 없다
- **"덮였는가"도 걸어보지 말고 재본다.** 폐허답게 지붕을 절반 넘게 걷어냈더니
  실제 덮인 바닥이 **25%**였고, 반대로 조금 남겼더니 97%가 되어 무너진 건물로
  안 읽혔다. 바닥을 격자로 훑어 광선을 쏘면 한 번에 나온다 (51%로 맞췄다)
