## 7. 리스크

| 리스크 | 대응 |
|---|---|
| 오픈월드 3D 생존은 상용 게임도 수년이 걸리는 초대형 장르 | 프로토타입 범위를 극단적으로 좁혀 코어 루프만 검증 (4장) |
| ~~**하드코어 초기화 + 장기 플레이의 충돌**~~ **해소 (v0.4)** | 완충안을 적용했다 — 조감도·기록 조각·되살린 흙만 계승하고 물자·건물은 초기화. 하드코어의 긴장은 그대로 두면서 이탈 이유만 없앴다 |
| 브라우저 성능 한계 (드로우콜, 메모리) | 인스턴싱 · 청크 언로드 · 오브젝트 풀링을 초기 구조에 반영 |
| 콘텐츠 제작량 폭발 | 절차적 생성 + 시스템 조합으로 콘텐츠 창발 유도, 수작업 최소화 |
| 폐허만 있는 월드의 시각적 단조로움 | 구역별 색조·구조물 밀도·잔해 종류를 다르게 하여 바이옴 대체 |
| 에셋 부재 | 도형 프리미티브로 끝까지 개발, 렌더링 레이어를 분리해 아트 교체 가능하도록 설계 |
