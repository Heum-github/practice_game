## 백엔드

`server/` — 프레임워크도 의존성도 없다. `node:http` 와 Node 24 내장 `node:sqlite` 만 쓴다.

**서버에 맡긴 것은 셋뿐이다.**

| 하는 일 | 왜 서버인가 |
|---|---|
| 세이브 보관 | 브라우저 저장소를 지워도, 기기를 바꿔도 살아남는다 |
| 월드 시드 발급 | 무엇을 플레이할지는 서버가 정한다 |
| 생존 기록 | 다른 사람과의 비교는 클라이언트가 집계할 수 없다 |

**서버로 보내지 않은 것**: 이동과 물리. 싱글플레이 게임에서 조작을 왕복시키면
조작감만 잃고 얻는 게 없다. 시뮬레이션은 전부 브라우저에서 돈다.

**서버는 전제가 아니다.** 통신이 실패하면 [Api](../../src/net/Api.ts)가 조용히
localStorage로 떨어진다. 백엔드를 끄고 `npm run dev:client` 만 돌려도 게임은 그대로 된다.
HUD 우하단 `저장` 항목이 지금 어느 쪽으로 저장되는지 보여준다.

| 엔드포인트 | 설명 |
|---|---|
| `GET /api/health` | 상태 확인 |
| `POST /api/session` | 플레이어 식별자와 시드 발급 |
| `GET · PUT · DELETE /api/save` | 세이브 읽기 · 쓰기 · 삭제 |
| `POST /api/runs` | 사망 기록 (기록 후 세이브 삭제 — 사망은 완전 초기화다) |
| `GET /api/records` | 명예의 전당 + 개인 기록 |

세이브는 **월드 전체가 아니라 시드 + 변경분만** 담는다 — 캔 노드, 지은 것,
가진 것, 시계. 지형과 폐허와 자원 배치는 시드에서 결정론적으로 다시 만들어진다.

데이터는 `data/eden.sqlite` 에 쌓인다 (git 무시).

지금은 프로토타입 규모에 맞춘 형태다. 유통을 가정한 계정·마이그레이션·검증
확장은 → [platform.md](platform.md).

### 자원 설계 메모

이 세계는 흙이 사라진 곳이라 자원 희소성이 보통 생존 게임과 반대다.

| 자원 | 양 | 재생 |
|---|---|---|
| 금속 잔해 | 흔하다 | 없음 |
| 빗물 | 흔하다 | 매일 아침 |
| 마른 풀 | 보통 (비옥한 땅에만) | 없음 — 대신 **수확할 때마다 나온다** |
| 흙 | 귀하다 | 없음 — **퇴비로만 늘어난다** |
| 통조림 | 유한하다 | 없음 |

유기물만 재생 칸이 비어 있지 않다. 땅에 난 것은 유한하지만 농사가 대를 낸다 —
마른 풀은 불을 먹이고, 퇴비를 거쳐 흙으로도 돌아온다.

그래서 **v0.3에서 세 자원의 상한이 모두 풀렸다** — 연료도 흙도 식량도
결국 밭에서 나온다. 거점이 자립하는 순간이 여기다.

통조림이 유한하다는 것이 첫 번째 시계다. 다 떨어지기 전에 농사를 지어야 한다.

고인 물은 수분을 채워주지만 **30% 확률로 포자병을 옮긴다**. 끓이면 안전하고 몸까지 덥지만,
불이 있어야 하고 한 번에 하나씩만 끓는다. 그래서 물은 "있으면 마시는 것"이 아니라
**불을 세울 때까지 참을 것인가**를 묻는 자원이 된다.
